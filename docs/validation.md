# v0.1.0 验证记录

日期：2026-11-12。验证目标：把可分享的规则、模板和工具交给一个不携带原项目聊天记录的独立任务，检查它能否完成新题目；同时验证导出链路的实际行为。

## 独立试跑

只提供本技能包与 `examples/brief.md`。执行任务没有读取原客户项目、聊天历史或个人记忆，也没有联网获取材料。它自行安排页序、提炼标题并制作「近邻工具图书馆」6 页虚构提案。

产物在 `examples/`：输入材料、页序地图、HTML、来源清单、高清总览与 PDF。来源清单区分练习设定、原创图形与拟议操作细节。

结果：

- 6 页 HTML 完整，全部检查通过。
- 6 张单页实际为 3840×2160；总览为 4080×3881。
- PDF 为 6 页，每页 2880×1620 pt，16:9；96 dpi 渲染即 3840×2160。
- 对 HTML 单页和 PDF 重渲染页进行了逐页目检：无缺图、缺字、遮挡、空白页或导航残留。
- 样例明确虚构、小样本及拟议状态；没有把访谈设定扩大成市场规模或把试点当作已完成成果。

这是同一模型环境中的独立上下文试跑，不等于已验证所有 AI 产品、模型或操作系统。

## 试跑推动的修正

1. 增加画布原点检查，防止整体边距导致截图被裁切。
2. 区分可见字形盒内溢出与真实裁剪，减少标题误报。
3. 补充 PDF 再渲染的命令及可选 Poppler 依赖说明。
4. 根据实际依赖要求，将最低 Node.js 版本明确为 20.9.0。

## 验证环境与边界

macOS；Node.js 24.22.1；Playwright 1.62.1；sharp 0.35.5；pdf-lib 1.17.1。重新安装了 npm 依赖；浏览器使用本机已经可用的 Chromium。此次不是全新操作系统的安装测试，Windows / Linux 字体与系统依赖仍需在目标环境检查。

自动检查无法识别所有视觉重叠，交付前仍需逐页目检。PDF 重渲染出现了 Type 3 字形边界警告，但样例的六页画面未见相应异常。照片真实细节受原始素材限制；公开样例只使用原创矢量图形。

本包的稳定交付路线为 HTML、PNG、总览和 PDF；未实现或验证可编辑 PPTX 导出。
