# 整套工作流

## 1. 提取事实与主张

先明确受众、使用场景、希望促成的理解或决定，以及已确定的页数、格式和原句。把材料分为：已证实事实、用户判断、拟议方案、未来愿景、待确认信息。

素材或资料缺失时，先做不依赖它的结构工作。仅对会改变方案方向的缺口提问；不要为每个版式选择反复确认。

## 2. 建立页序地图

每页记录六件事：

| 项目 | 要回答的问题 |
| --- | --- |
| 一句话主张 | 观众离开这页记住什么？ |
| 证据 / 场景 | 凭什么相信，或怎样理解？ |
| 页面角色 | 命题、解释、证据、场景、转折还是收束？ |
| 与前后页的关系 | 前页提出的问题怎样被接住？ |
| 视觉结构 | 用哪种原型，主素材是什么？ |
| 信息状态 | 哪些是真实进展，哪些属于拟议或愿景？ |

页序从受众认知出发。避免按源文档的小标题机械切页；也不要把宏大愿景写成长篇虚构故事。找到一条能从现状走到主张、再走到具体行动的线。

## 3. 提炼文案与信息结构

先完成每页主标题，再配必要证据与解释。把跨模块重复内容合并，明确并列、因果、先后、对照关系。为每张主图写一句用途；没有用途的装饰先拿掉。

与用户已经确认的语言保持一致。定稿阶段的“删除四个字”按精确修改执行，不借机重写相邻段落。

## 4. 锁定视觉参数

从 `assets/template.html` 复制新文件，选定字体、颜色、边距、字号、圆角和阴影。全套共享这些参数。内容页、图文页和命题页仍可有不同构图。

跨平台字体变化会影响字宽和换行，必须以实际渲染结果重新检查。素材用相对路径；本机个人目录、账号信息和运行库绝对路径不能成为可分享文件的依赖。

## 5. 三类样页校准

先做一张命题页、一张图文页、一张复杂信息页。它们覆盖字体尺度、素材质感和信息密度，适合发现整套问题。

- 用户希望先看风格：先交这几页；收到反馈后推广到全套。
- 用户已授权直接完成：内部检查后继续，无需增加审批环节。
- 已有明确且获认可的样页：直接沿用，不重复提案。

初稿素材可以适度降低生成成本，但标题和正文始终保持原生。总览图需要足够清晰，用户应能放大阅读。

## 6. 全套完成与局部修订

先看总览：是否有重复轮廓、密度过高、黑白节奏单调或某页明显脱离系统。再逐页看全尺寸：断行、图标、来源、对齐、裁切与素材真实性。

局部修改只重做受影响页面，但必须重新生成关联的总览与最终文件。记录哪些页面发生内容变更，避免把旧预览和新 PDF 混在一起。

## 7. 输出与验收

运行工具检查页数、页面标识、溢出、缺图与浏览器错误。自动检查辅助定位，不能取代目检。

按用户要求导出 HTML、PNG、总览或 PDF。4K 单页必须从原生页面以 3840×2160 渲染。PDF 需检查实际页数、16:9 比例、空白页、导航残留，以及关键修改是否进入最终版本。

渐变文字、阴影、透明层和深色页是导出重点。出现渲染瑕疵时只修导出路径，保持已批准设计；必要时局部高分辨率处理，其他文本和图形继续保留原生。

完成 [质检清单](qa-checklist.md) 后交付。必要时说明照片原始清晰度、字体替代或局部渲染等实际限制；不要把工具内部过程堆进客户页面。
