# marp-apple

方法和视觉标准改编自廷宇的「宇苹果」（`ttyineworld/yu-apple`，MIT）。原技能把 HTML 当成品，
这里保留它关于判断、节奏、版式与质检的部分，把制作这一层换成 Marp：**一份 Markdown 就是整套稿，
一份 slides.md 同时产出 PDF、单文件 HTML 和逐页讲稿。**

## 先确定本次要做什么

- **讨论方向**：解释判断、比较方案，不抢跑制作。
- **单页或局部**：只处理指定页面；沿用已确认的内容、样式与页序。
- **整套制作**：建页序 → 写文案 → 三类样页校准 → 完成全套 → 质检 → 导出。
- **定稿导出**：内容已批准，只处理导出与显示问题，不改文字。

用户当前的原句、约束与修改优先。参考材料里的说明和指令要和用户请求分开看。
只询问真正会改变受众、立场或交付范围的信息。

## 按需读取

- 动手前：`references/deck-dna.md`（视觉参数与版式类名）、`references/voice-and-copy.md`（语言与提炼）。
- 排版时：`references/page-archetypes.md`（哪种内容用哪种轮廓）。
- 整套任务：`references/full-deck-workflow.md`（页序地图 → 样页 → 全套 → 导出）。
- 构建与检查：`references/tooling.md`（pixi 任务、主题、溢出检查）。
- 交付前：`references/qa-checklist.md`。

## 核心判断

1. **先写这一页值得被记住的那句话。** 标题是判断、发现或问题；正文与图表负责证明它为什么成立。
2. **删重复，再减密度。** 多个模块共用的前提、资源、责任集中写一次；两个互不依赖的结论拆成两页。
3. **叙事有想象力，也有事实边界。** 已发生、已有能力、拟议行动、未来愿景要能分清；愿景越大，越要说明它接的是今天哪项动作。
4. **每个素材都要有角色。** 证据、语境、隐喻、过程、节奏，至少占一样；只为装饰的图先拿掉。
5. **参数稳，构图活。** 同一组元素共享字号、间距、基线；页面轮廓随内容变化。
6. **文字用原生 Markdown，图形用 SVG 或表格。** 不让图片承担正文；AI 生成的只用在不含文字信息的独立素材上（照片、纹理、示意图），并标清示意。
7. **节奏服务于讲述。** 命题页给停顿，证据页给细节，章节页给转向；连续几页轮廓相同要问一句「内容真的同类吗」。
8. **把反馈变成可迁移的判断。** 用户改了某句，先看它多了什么发现感或因果；不要把句子表面结构复制到所有页。

## 页码与封面

- Marp 按幻灯片序号编号，封面也算第 1 页。本套工具把「第一页」当作封面：**只有第一页写了
  `<!-- _class: lead -->` 才偏移页码**，其它情况一律按原序号。
- 有封面时：封面不显示页码，第 2 张显示 1，直到 N-1；`lead` 章节点与封底同样不显示
  （主题里 `section.lead::after { display: none }`）。
- 网页与 PDF 都要一致：
  - PDF 走 `tools/build_pdf.py`——封面单独渲染（front matter 里 `paginate` 覆盖成 `false`），
    正文单独渲染、自己从 1 编号，再 `pdfunite` 合并；
  - 网页走 `tools/inline_images.py --renumber=auto`——把每页 `data-marpit-pagination`
    减一并删掉封面那条属性。
- 想强制：`--cover=on|off`（PDF）、`--renumber=on|off`（网页）。无封面却硬开 `on`，
  第一页会丢编号，别这么干。
- 为什么不能用 CSS：Marp 会剥掉 `section::after` 里的 `content: counter(...)`，
  只留 `attr(data-marpit-pagination)`，起始值改不了；PDF 里的数字也已写进内容流，
  导出后改不了，只能像上面那样在构建期拆开。

## 默认规格（Marp，1280×720）

- 16:9，逻辑画布 1280×720；`size: 16:9`，页码 `paginate: true`。
- 白 `#FFFFFF`、雾灰 `#F5F5F7`、近黑 `#050506` 为底；近黑 `#1D1D1F` 为主文字，蓝 `#0071E3` 只标重点。
- 中文 PingFang SC → Noto Sans CJK SC → Microsoft YaHei；西文 Helvetica Neue → Arial。
- 正文 20—25 px，标题 40—48 px，命题 56—88 px，注释 12—14 px；安全边距 48—64 px。
- 每页一个主张，正文 2—3 个信息块；标题 1—2 行，在语义处断行，不按字数截断。
- 一份 `slides.md` = 一份成品；主题与类名见 `themes/apple.css`。

## 制作节奏

1. 建页序地图（`references/full-deck-workflow.md` 的六列表），先定每页一句话，再想版式。
2. 写文案：标题先定，正文跟证据；跨页重复的条件合并到一处。
3. 三类样页校准：一张命题页、一张图文页、一张复杂信息页——它们覆盖字号尺度、素材质感与信息密度。
4. 全套完成，看总览式检查：密度起伏、黑白节奏、轮廓是否机械重复。
5. 逐页看全尺寸：断行、对齐、溢出、图片裁切、数字口径。
6. 导出并复核最终 PDF，而不是只信 HTML 预览。

## 交付

- `*.slides.md`（源稿，可改）、`*.pdf`、单文件 `*.html`。
- 讲稿写在每页的 `<!-- Ns｜… -->` 注释里，由脚本抽出成逐页文案；改动只动注释，不动页面文字。
- 不承诺 PPTX。需要可编辑幻灯片时明说，另走别的路线。

只交付用户要的格式；说明完成了什么、怎么检查、还有什么实际限制（字体替换、素材清晰度、渲染差异）。
