# 整套工作流

## 1. 提取事实与主张

先明确受众、场景、希望促成的理解或决定，以及页数、时长、交付格式和已定原句。
把材料分成：已证实事实、用户判断、拟议方案、未来愿景、待确认信息。

素材缺失时先做不依赖它的结构工作。只对会改变方案方向的缺口提问，
不为每个版式选择反复确认。

## 2. 建立页序地图

每页记六件事，写在同一张表里再动手：

| 项目 | 要回答的问题 |
| --- | --- |
| 一句话主张 | 观众离开这页记住什么 |
| 证据 / 场景 | 凭什么相信，或怎样理解 |
| 页面角色 | 命题、解释、证据、场景、转折、收束 |
| 与前后页的关系 | 前页的问题怎样被接住 |
| 版式 | 哪种类名与轮廓，主素材是什么 |
| 信息状态 | 哪些是已发生，哪些是拟议或愿景 |

页序从受众认知出发，不按源文档小标题机械切页。

## 3. 写文案

先定每页主标题，再配必要证据与解释。合并跨模块重复，写清并列、因果、先后、对照。
为每张主图写一句用途；没有用途的先拿掉。

与用户已确认的语言保持一致。定稿阶段「删四个字」就删四个字，
不借机重写相邻段落，也不把「顺便改顺」当成帮忙。

## 4. 锁定视觉参数

参数来自 `references/deck-dna.md`，由 `themes/apple.css` 实现：
字号、间距、圆角、颜色、页眉页脚都在主题里改一次，正文只写结构类名。

同一份稿子里不出现两种字体、两套强调色或两种页码风格。
没有品牌要求时不要临时加装饰条、图标墙和渐变背景。

## 5. 三类样页校准

先做一张命题页、一张图文页、一张复杂信息页。它们覆盖字号尺度、素材质感与信息密度。

- 用户要先看风格：只交这几页，等反馈再推全套。
- 用户已授权做完：内部检查后继续，不额外增加审批环节。
- 已确认过样页：直接沿用，不重复提案。

## 6. 全套完成与局部修订

先通看：轮廓是否机械重复、密度是否一直偏高、黑白节奏是否单调、是否有页面脱离系统。
再逐页看全尺寸：断行、对齐、溢出、图片裁切、数字与口径。

局部修改只重做受影响页面，但必须重新生成 PDF、HTML 与逐页文案，
避免旧预览与新稿混用。改完在提交说明里写清改了哪几页、为什么。

## 7. 讲稿与页面分离

页面文字是给观众看的，讲稿是给自己说的。两者不要互相复述：

- 页面写结论、证据、关系；讲稿补因果、判断过程、被追问时的边界。
- 讲稿写在每页注释 `<!-- Ns｜正文 -->` 里（`N` 是该页标注秒数），由脚本抽成逐页文案。
- 只改讲稿时不动页面文字，重出 PDF 后页数与版面应完全不变——这是检查有没有误改的手段。

## 8. 导出与验收

- `pixi run pdf` → 16:9 PDF；`pixi run html` → 内联图片的单文件 HTML；
  `pixi run notes` → 逐页文案；`pixi run check` → 溢出与页码检查。
- 先看 PDF 页数与尺寸，再逐页目检；HTML 预览正常不代表 PDF 正常。
- 导出后核对：页码从正文 1 开始、无空白页、无浏览器页眉页脚、代码块不横向溢出。
- 全部通过后按 `references/qa-checklist.md` 收尾，说明仍存在的限制
  （字体替换、素材清晰度、投影比例）。
